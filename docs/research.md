# 租房版图：调研与选型

## 2026-11-14 全屏地图改版

根据最新交互要求，前端改为只有地图的沉浸式界面。全国、省、市仍由 DataV 行政区边界与 D3 投影展示，自动适配全视野；右上角为行政区路径，首页不显示路径。各级通过鼠标滚轮缩放、左键拖动，只有区县加载房源数据。

用户已提供高德 Web JS API 配置，使用 `.env.local` 本地环境文件保存并排除版本管理。区县使用真实高德 2.0 SDK、`amap://styles/darkblue`，显示道路、建筑和地名，并通过区县 Polygon 适配视野、行政区 mask 聚焦区域。高德 Logo、版权保留；房源使用原生覆盖物呈现光点，点击才显示详情。SDK 仅在进入区县后加载。

已实际验证 SDK 加载、真实地图道路和中文地名渲染；不是通过示意线条模拟街道。示例房源的中心点偏移可能超出狭窄区县，对示例光点单独检查多边形包含关系，必要时使用区县内部代表点，真实用户坐标不自动移动。

## 产品与交互

核心任务是从地理范围发现居住信息。首页以全国行政区块为主，省份可进入地级市，地级市可进入区县，区县作为房源筛选的最后一级。直辖市直接进入区县。所有层级都提供房源列表，避免用户必须反复点击后才能看到信息。

地图下钻、城市搜索、面包屑、返回上级与浏览器返回同步。租赁类型、预算、卧室数、特色、关键词、排序同时影响地图上的统计和房源列表。移动端提供地图 / 列表切换，避免小屏并排。

首版目标为验证完整流程：探索 → 筛选 → 查看 → 收藏，或发布 → 数据入库 → 在对应区域找到。没有引入付费、预约、真实身份认证等尚未实现的按钮。

## 一、行政区划与地图数据

资料：[DataV.GeoAtlas 行政区域选择器](https://datav.aliyun.com/portal/school/atlas/area_selector)、[全国 GeoJSON](https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json)。两者均实际访问成功。

已验证全国接口含 34 个省级区块及附加边界线；properties 提供 `adcode`、`name`、`level`、`parent`、`center` / `centroid`、`childrenNum`，可建立父子关系。全国、省级和部分城市的区县边界已在本地缓存，未缓存的城市从固定 DataV 地址按需获取。行政区代码在后端严格校验，不接受任意远程 URL。

区县没有下一层行政地图时，保留所在市边界并高亮当前区县。台湾省当前数据源没有提供该接口下的子区块；仍可选中省级区块并查看该区域列表，界面不虚构边界。数据源并非实时行政区划发布服务，边界与名称可能滞后，正式上线应制定版本更新策略，核实数据许可及公开地图适用要求。

资料：[D3 d3-geo 官方文档](https://d3js.org/d3-geo)、[Apache ECharts 地理组件](https://echarts.apache.org/en/option.html#geo)。均实际访问成功。

选择 D3 地理投影 + SVG。当前主要对象是 34 个省份与省 / 市下的有限区块，SVG 足够轻量，便于键盘访问、鼠标悬浮、精确点击、边界高亮和自定义科技风格。适配 GeoJSON 多边形方向，并单独展示南海诸岛示意。没有接入底图瓦片服务，因此本地启动不依赖地图 API Key。

ECharts 适合统计图表和现成地图系列，但当前交互与视觉以行政区块为核心，D3 提供的控制更直接。后续若加入街道、通勤路线、地图范围内大量房源，需再评估合规地图服务 SDK 与房源聚合，而非继续扩大 SVG 点的数量。

## 二、前端

资料：[Vite 官方入门](https://vite.dev/guide/)。实际访问成功。

选择 React 19 + TypeScript + Vite 7，配合 Lucide 图标与原生 CSS。地图交互、筛选、收藏、弹窗、发布表单有较多关联状态，React 便于组合；TypeScript 约束行政区和房源契约。当前为 Go API 驱动的交互式应用，不需要前端另设 Node 服务或 SSR。

视觉：低亮度黑蓝背景、荧光蓝主色、紫色合租标记、绿色转租标记；避免全屏高亮造成阅读疲劳。系统字体始终可用，地图和房源图片本地提供，减少外部资源对核心流程的影响。

## 三、Go 服务

Go 标准库 `net/http` 提供方法与路径路由，避免为简单 API 引入额外 Web 框架。数据库使用 `database/sql`，分别提供 pgx PostgreSQL 和纯 Go SQLite 驱动。采用上下文超时、请求体限制、服务端字段校验、同源发布校验和 HttpOnly 会话 Cookie。

接口职责：行政区索引、地图边界、房源检索 / 统计 / 分页、房源详情、发布与本地浏览器会话。前端静态产物可由同一 Go 服务托管，开发模式则由 Vite 转发 API。

## 四、数据库

资料：[PostgreSQL 索引类型](https://www.postgresql.org/docs/current/indexes-types.html)、[PostGIS 文档](https://postgis.net/documentation/)、[SQLite 适用场景](https://www.sqlite.org/whentouse.html)。均实际访问成功。

**正式部署选择 PostgreSQL。** 租房信息是结构化数据，类型、价格、面积、所属行政区适合关系表；未来账号、收藏、审核和举报也有明确关系。PostgreSQL 具备事务、多连接并发和成熟索引能力。后续若加入距离、地铁站点、视口边界检索，可启用 PostGIS 的 `geography(Point,4326)`、GiST 索引和 `ST_DWithin`。

当前行政区下钻仅依赖行政区代码，不需要提前安装 PostGIS；经纬度以数值保存，避免把未用到的组件变成启动门槛。提供 PostgreSQL 17 的 Compose 配置及持久卷。当前机器未安装 Docker / PostgreSQL，因此完成了 SQL 参数适配测试，没有把 PostgreSQL 实例集成测试标记为已通过。

**本地体验提供 SQLite 模式。** 用户无需预先安装数据库即可运行真实持久化功能；SQLite 开启 WAL、忙等超时、单连接，适合本地单进程体验。两者共用字段结构。内置样本仅 216 条，首版服务端将记录读出后执行组合筛选和统计；大规模上线应改为数据库 WHERE / 聚合 / 分页，并增加连接池、查询计划与并发测试，不能以样本运行效果推断生产吞吐。

## 五、房源与图片

内置 18 个城市共 216 条示例房源，用于验证不同租赁类型、不同预算及地图分布。全部 `isDemo=true`，前端明确展示示例标识，联系方式不可用于真实联系。用户新发布记录 `isDemo=false`，但尚无人工核验，因此详情会提示核验信息。

室内展示照片来自 [Unsplash](https://unsplash.com)，已下载至 `data/images`；图片 ID 记录在 `scripts/download-data.mjs`。这些照片不是房源实拍，新发布表单也明确说明当前使用通用展示图片。

## 六、下一阶段

真实运营前需要完成：账号与权限、手机号或邮箱验证、发布审核、举报与下架、真实房源图片上传、数据授权、隐私政策及房源信息核验。当前“我的发布”使用当前浏览器的会话 Cookie 关联，收藏只保存在当前浏览器，不伪装成跨设备账号系统。公开绑定地址默认关闭发布；本地回环地址默认允许体验发布。

本项目先实现可用的地图找房流程，后续运营版的业务和法律要求应在具体上线范围确认后补齐。
