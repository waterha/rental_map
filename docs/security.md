# 公开部署安全说明

本次实现针对应用层恶意请求、账号攻击、恶意上传、文件泄露和 SQL 注入。没有“永不被攻击”的保证；应用收到请求之前的链路洪泛需要阿里云清洗 / WAF。本文件不表示已经操作了你的阿里云或宝塔服务器。

## 代码中的防护

| 范围 | 默认行为 |
|---|---|
| 请求准入 | 每 IP 每秒补充 10 次、突发 60 次；写操作额外每 2 秒补充 1 次、突发 30 次。单进程全局每秒 200 次、突发 400 次。超额 429，附 Retry-After |
| 有界内存 | 最多记录 16384 个来源，闲置超过 5 分钟清理；达到容量时拒绝新来源。IPv6 同一 /64 共用额度，防止轮换地址绕过 |
| 并发 | 总请求 64、账号写操作 4、上传 2；超额直接 503，避免无限排队、图片解码或 bcrypt 堆积 |
| IP 来源 | 默认不信任转发头；只信任 TRUSTED_PROXIES 中列出的代理，并只读该代理覆盖的 X-Real-IP。原有账号 IP 限流也使用验证后的地址 |
| 账号 | 密码 bcrypt、会话和验证码只存摘要、HttpOnly / SameSite Cookie；验证码 120 秒、最多错 5 次；错误验证码先拒绝，不消耗密码哈希计算。发信全站最多 100 次 / 小时，另有来源 / 邮箱限制 |
| 请求约束 | 地址最多 4096 字节，HTTP 请求头 16 KiB、读头 5 秒；普通业务请求上下文和连接读写期限 20 秒、上传 90 秒，避免慢速发送占满并发。账号 JSON 最多 4 KiB、上传总请求最多 26 MiB |
| 上传 | 必须登录、1–5 张 JPEG/PNG、单张 ≤5 MiB、≤1200 万像素；服务端重新编码、限制输出大小、移除 EXIF/GPS 和原名；存储总量默认 1 GiB，重启统计已有文件，预留额度时加锁，失败释放 |
| 文件 | 仅公开构建产物、示例图和随机命名用户照片；无目录索引，禁止点文件、数据库、runtime、源码映射等路径；使用 os.Root 阻止符号链接越出公开目录 |
| 数据库 | 所有用户值通过参数绑定；排序由固定白名单决定。详情通过主键查询，列表只取 9 条详情和最多 150 个标记，统计在 SQL 内完成；列表不批量返回联系方式，详情按产品要求公开联系方式 |
| 生产校验 | APP_ENV=production 必须提供 PUBLIC_ORIGIN，必须是 HTTPS；校验 Host、来源和受信代理的协议。会话 Cookie 强制 Secure；生产必须 PostgreSQL，拒绝超级用户、建库 / 建角色 / 复制 / 绕过 RLS 权限，以及能切换至这些角色或内置 pg_* 角色的成员关系 |
| 浏览器 | CSP、禁止被第三方框架嵌入、nosniff、权限限制和 HTTPS HSTS。高德 SDK 需要指定的远程域名、动态样式和 unsafe-eval，这是当前 SDK 的策略例外；不允许任意远程脚本 / 内联脚本 |
| 地图缓存 | 行政边界和地铁同一区域并发冷加载合并一次，无可用缓存时失败冷却 30 秒；新增边界和索引写入 runtime，便于只读部署；固定上游地址，限制响应大小 |
| 依赖 | Go 最低 1.26.11，更新 pgx、x/crypto、x/text、SQLite；CI 执行漏洞扫描、静态检查、测试和隐私检查 |

限流和磁盘额度是**单实例**状态，重启会重置请求令牌，磁盘用量会重新统计；上传目录不能由多个进程共同写入。多副本需要共享限流 / 存储配额方案，不能直接扩大实例数就认为限额仍然相同。全站发信额度保存在数据库中。准入限制不能阻止未进入 HTTP 处理器的连接洪泛。SQL 上下文取消取决于驱动及时响应，生产 PostgreSQL 另配语句超时。

公开房源的照片、位置和联系方式本来就允许访客访问；这些可见内容无法做到绝对防爬。限制批量列表中的联系方式减少不必要曝光，账号邮箱、密码哈希、验证码、会话、数据库文件均不通过房源 API 返回。

## 宝塔：必须匹配的应用配置

不要把仓库根目录设置为站点目录，不要在该站点开启 PHP。让 Nginx 反向代理到 `127.0.0.1:8080`，关闭公网 8080、5173、5432。应用以独立非 root 用户运行。宝塔 HTTPS 证书和重定向由你的站点配置管理。

服务端环境示例（真实密码存服务器本地，文件权限 600，不入库）：

```dotenv
APP_ENV=production
ADDR=127.0.0.1:8080
PUBLIC_ORIGIN=https://rental.example.com
TRUSTED_PROXIES=127.0.0.1/32,::1/128
AUTH_COOKIE_SECURE=true
DATABASE_URL=postgres://rental_app:YOUR_APP_PASSWORD@127.0.0.1:5432/rental_atlas?sslmode=disable
ALLOW_PUBLISH=true
DATA_DIR=/opt/rental-atlas/data
STATIC_DIR=/opt/rental-atlas/dist
RATE_LIMIT_RPS=10
RATE_LIMIT_BURST=60
MAX_CONCURRENT_REQUESTS=64
MAX_CONCURRENT_AUTH=4
MAX_CONCURRENT_UPLOADS=2
UPLOAD_STORAGE_MB=1024
```

`rental.example.com` 换成真实域名，只支持指定的单一域名；其他域名先由 Nginx 跳转。HTTPS 终止在 Nginx 时，它必须覆盖 `X-Real-IP` 和 `X-Forwarded-Proto`；直接把客户端传来的头转交后端会破坏信任边界。应用配置错误会拒绝启动或拒绝请求，而不会静默关闭防护。

`deploy/baota-http.conf` 放入 Nginx **http 层**，`deploy/rental-proxy.conf` 复制到其中标明的 include 路径，`deploy/baota-locations.conf` 合入宝塔的 **HTTPS server 层**，替换该站点原有冲突的代理 / 静态扩展规则。先 `nginx -t`，通过后 reload。不要直接覆盖宝塔的证书设置或其他站点。模板日志仅记录方法、路径和状态，不记录查询参数、Cookie、请求体或验证码；为日志设置轮转与保留期。

如果阿里云 CDN / WAF 在 Nginx 前：Nginx 的 real_ip 模块只能信任阿里云给出的实际代理网段，再使用供应商指定的真实客户端 IP 头；源站安全组只允许代理回源。**不要**配置 `set_real_ip_from 0.0.0.0/0`，也不要盲目信任任意 X-Forwarded-For。若没有正确恢复 IP，多个访客会被视为同一个来源而共同限流。应用只需要信任本机 Nginx，不需要信任全互联网。

`deploy/rental-atlas.service` 提供非 root、只读系统目录、进程 / 内存上限的 systemd 模板。先创建 `rentalatlas` 系统用户、`/opt/rental-atlas/data/runtime`（归该用户）和 `/etc/rental-atlas/server.env`（600）；配置数据库后再启用。部署二进制须用 Go 1.26.11+ 构建。普通配置和程序归管理员所有，仅 runtime 可写。若通过宝塔进程管理器运行，应设置相同的用户和资源限制。

数据库连本机 / Docker 私有网络时，示例允许 `sslmode=disable`；连接远程数据库必须改用 `sslmode=verify-full` 并配置 CA，不能把该本地示例照搬到公网连接。数据库和备份开启阿里云磁盘 / RDS 加密、单独权限，并保存加密异机备份；代码中的密码哈希不能代替数据库或备份加密。

## 数据库账号与已有部署

应用需要在自身 schema 创建表以执行当前迁移，但不需要超级用户、其他数据库权限或任意文件读写权限。`deploy/postgres-init.sh` 为**全新** Compose 数据卷建立 `rental_app`，只允许连接 `rental_atlas`，拥有 `rental` schema，连接上限 16、语句超时 15 秒、锁等待 5 秒。管理员密码和应用密码分开；Compose 不暴露数据库端口，应用容器只读，runtime 使用持久卷。

生产启动会拒绝原先的超级用户 `atlas`。已有库必须先备份，并由数据库管理员创建受限用户、授予当前应用表 / schema 的必要权限，修改 DATABASE_URL 后验证登录、上传、房源读取，再停用旧应用凭据。**不要删除数据库卷或盲目重建库**。初始化脚本不会替你迁移已有数据 / 用户。在宝塔自建 PostgreSQL 中可参考该脚本，由管理员按实际库名执行；不要授予 `pg_read_server_files`、`pg_write_server_files`、`pg_execute_server_program`、`pg_read_all_data` 等跨应用权限。

## 高德和历史凭据

Web JS 的客户端 Key 会被浏览器使用，无法在保留该 SDK 的同时把它当作服务端秘密；必须开启域名授权和配额告警。SMTP 授权码、数据库密码和会话密钥始终只在后端。曾在聊天中提供过的 SMTP / 地图凭据，正式上线应在相应控制台重新生成后填入服务器本地环境文件；本次没有替你撤销或更换旧凭据。

## 验证与剩余边界

本次加入针对限流、伪造 IP、IPv6 轮换、并发拒绝、限流表回收、跨站写入、私有文件、目录索引、逃逸链接、存储配额、SQL 输入和公开数据最小化的自动化检查。保留真实高德 SDK、注册 / 登录 / 发布 / 拖动等端到端检查。漏洞扫描只能反映扫描时已知信息，不能证明不存在未知漏洞。CI 在 Linux 执行 race 检测；本地 Windows 没有 C 编译器，不能运行 race。本地未安装 Docker / Nginx，模板仍须在目标宝塔执行配置检查与数据库联调。

单服务器代码层可以缓解 CC、暴力登录、垃圾邮件和恶意上传；带宽被打满、内核连接资源耗尽、数据库管理员凭据泄露或服务器 root 被控制，必须靠云防护、网络隔离和运维权限处理。上传总量接近上限时会拒绝新照片，应先备份、清理确认无用内容或扩容，不要为了恢复发布直接关闭限额。
