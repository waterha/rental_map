# 房源数据独立加载

区县页面底部提供紧凑的全部、整租、转租、合租切换条，不添加侧栏。选择类型时请求项目自己的 `GET /api/listings?region={districtCode}&type={type}`，只替换房源光点；再次点击已选类型不发起请求。加载中清除旧类型光点，结果为空时显示暂无房源，失败时提供单独的“重试房源”。

查看详情只请求 `GET /api/listings/{id}`。详情失败后的“重新加载房源”重新请求同一个房源，保留弹窗，不刷新列表、行政区信息或地图。关闭详情、切换筛选和离开区县取消待完成请求；超时提供重试，旧请求不能覆盖新结果。

## 为什么要改

改动前，正常查看详情已经不重建地图；但是详情失败后的重试会增加 App 的全局 reload 状态，重新请求行政区列表并替换 Region 对象。高德地图初始化 effect 又依赖 `region.center` 数组引用，这条链路可能重新创建底图和重置视野。

现在房源状态与网络请求由 `DistrictRentals` 独立管理，详情由 `ListingPopover` 展示，App 只管理行政区导航。列表和详情重试均无法触发 App 的地图重试状态。DistrictMap 使用 memo、稳定的回调和空标记列表，初始化依赖地区代码、中心经纬度值、边界及显式地图重试；房源标记仍由独立 effect 增删。详情状态变化不会重新渲染地图，类型更新不会调用地图构造器、销毁、设置遮罩、适配视野或变更相机。示例光点的边界判断缓存标准化后的边界，避免每个光点重复标准化。

这项优化消除房源操作引发的不必要地图初始化，不承诺高德零用量或特定节省比例。首次打开区县、主动重试底图，以及用户拖动缩放，仍可能请求高德资源。离开区县后再次进入仍按当前逻辑新建地图，跨区县实例复用不属于此次改动。

## 验证

生产构建与 22 项隔离浏览器测试通过。新增 3 项房源用例：

- 在 SDK 生命周期替身中统计地图创建、销毁、遮罩、适配、相机与模拟资源加载调用。查看详情、关闭、详情重试、类型切换及列表重试后这些计数均未增加，行政区请求也未增加，画布节点保持连接。
- 延迟列表与详情响应，验证快速切换、关闭重开后旧数据不能覆盖当前选择。
- 在真实高德底图中开启地铁，执行详情失败重试和类型切换，验证原画布与地铁站点节点仍保持连接，地图中心、缩放及地铁开关不变。另检查手机尺寸下筛选条不超出视口。

隔离测试禁用真实邮件，结束后关闭测试服务。复测执行 `npm run test:e2e:isolated`。
