# 房源管理与管理员

房源详情窗口左上方提供铅笔（编辑）和垃圾桶（删除）图标。访客及其他发布者看不到图标；房源发布者可管理自己的房源，管理员可管理所有房源。删除需再次确认，成功后移除地图光点并刷新房源统计，不重新加载底图。

编辑表单回填原资料和照片，可修改标题、描述、租金、面积、户型、出租类型、出租身份、房屋类型和联系方式，支持保留、移除与追加照片，总数仍为 1–5 张。编辑保留房源位置、发布者和发布时间，避免变更归属或移动到其他区县。

## 配置管理员

在服务器环境或被 Git 忽略的 `.env.server.local` 中设置 `AUTH_ADMIN_EMAILS`，值为逗号分隔的完整邮箱地址。只支持已配置允许注册的邮箱域名；空值表示没有管理员。重启后生效，移除邮箱即撤销权限，现有会话的下次请求也会重新读取服务器权限。

若账号不存在，可同时临时设置 `AUTH_ADMIN_BOOTSTRAP_EMAIL` 和 `AUTH_ADMIN_BOOTSTRAP_PASSWORD`，其中邮箱必须在管理员列表中，密码为 10–72 字节。服务器启动时直接创建管理员账号并以 bcrypt 保存密码。此操作表示服务器维护者已确认账号归属，不发送注册验证码；公众注册仍须邮箱验证码。已有账号的密码不会被覆盖。创建完成后移除这两个临时配置，只保留管理员列表。不要将任何实际邮箱、密码写入公开仓库或以 `VITE_` 前缀配置。

## 接口权限

- `GET /api/auth/me`、注册及登录结果包含 `role: user | admin`。
- `GET /api/listings/{id}` 返回当前请求者的 `canManage`，不公开发布者账号或邮箱，禁止共享缓存。
- `PUT /api/listings/{id}` 使用与发布相同的 multipart 数据，`images` 只能包含此房源已有照片，`photos` 为新增照片。
- `DELETE /api/listings/{id}` 删除房源、附属资料和上传照片。

编辑和删除要求有效会话、同源请求、部署启用房源管理，并受频率、并发、上传大小、图像解码及存储额度限制。无会话返回 401，无管理权限返回 403，不存在返回 404。SQL 同时约束房源 ID 与当前用户归属；客户端提交的用户身份或管理员声明不决定权限。
